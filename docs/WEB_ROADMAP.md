# MOIMLOG Web/PWA 로드맵

기준일 2026-11-26. 교회 소그룹 순장 약 6명에게 Web/PWA를 배포하며 월 운영비 5,000원 이하를 목표로 한다.

## P0. 저장소 정리와 개발 기록 보존

iOS 마지막 커밋에 Git 태그를 게시하고 복원 파일을 비교한다. 기존 API, 녹음 흐름, SQLite 볼륨을 보존한다. 빌드·테스트와 배포 설정 점검 결과를 PR에 기록한다.

## P1. 모바일 Web/PWA 사용성 검증

실제 iPhone Safari 및 홈 화면 설치 상태에서 화면 폭 320~430px, VoiceOver, 로그인 유지와 만료 후 재로그인, 마이크 권한 거부와 재허용, 연결 끊김 안내를 확인한다. Manifest·아이콘·서비스 워커 등록과 업데이트를 점검한다.

## P2. 서버 측 초대제 계정 및 보안

서버에서 유효한 초대를 요구하고 관리자만 일회용·만료·취소 가능한 초대를 발급하도록 한다. 첫 관리자는 운영자가 콘솔에서 실행하는 별도 관리 명령으로 생성하고, 기존 사용자 지정 또는 초기 생성 절차와 중복 실행 방지를 검증한다. 순장 프로필 역할과 관리자 권한은 별도로 관리한다. 계정 두 개로 모임, 녹음/재시도, 양식, DOCX 접근과 세션 만료·로그아웃을 검증한다. 서버 검증이 완료된 뒤 가입 경로의 Caddy 정책을 조정한다.

## P3. 녹음 안정화, 재전송 및 파일 업로드

화면이 활성화된 웹 녹음과 별도 녹음 파일 업로드를 운영 경로로 유지한다. AudioWorklet 구간 분할, IndexedDB 저장과 재전송을 유지한다. 지원 환경에서 Screen Wake Lock을 사용하고, 화면 복귀 시 재획득을 시도한다. 페이지 비활성화, 마이크 트랙 중단, AudioContext 정지와 저장 상태를 표시하고 복귀 시 재개·업로드 방법을 안내한다. iPhone 화면 잠금·백그라운드에서 마이크 지속을 지원 범위에서 제외한다. 실기기에서 30·60·120분 녹음과 통화·앱 전환·네트워크 단절·새로고침 후 재전송을 검증한다.

동시 녹음은 Groq Free 조직 한도에 따라 대기열에 머물 수 있다. 대기·실패·재시도 상태와 6명 부하를 검증한다. 전사문 저장이 확인된 원본은 짧은 복구 유예 후 서버와 기기에서 삭제하고, 실패·재시도 대기 원본은 정해진 기간 동안 보존하는 정책을 설계한다. SQLite 공간 회수, 백업의 보관·만료와 삭제 데이터의 복원 시 처리도 검증한다.

## P4. Groq 분석과 DOCX 종단 간 테스트

동의를 받은 한국어 음성으로 녹음 또는 업로드 → 전사 → 화자 확인 → GPT-OSS 초안 → 순장 편집 → 실제 교회 원본 양식의 DOCX 생성·다운로드를 검증한다. 429, 분석 실패, 재시도와 기존 보고서 보존을 확인한다.

## P5. Oracle 백업, TLS, 운영 안정화 및 6명 배포

동일 Compose 프로젝트와 데이터 볼륨을 유지한다. SQLite와 계정별 파일을 일관되게 백업하고 격리 환경에서 계정·기록·양식·녹음을 복원해 검증한다. Caddy TLS 자동 갱신, 외부 HTTPS 및 8000 접근 차단, SSH 허용 범위, 재부팅 복구, 비용 및 Groq 한도를 점검한다. 검증을 마친 후 순장 6명을 초대한다.
