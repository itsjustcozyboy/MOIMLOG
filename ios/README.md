# MOIMLOG iOS

SwiftUI 네이티브 앱입니다. 기존 FastAPI 서버의 인증, 프로필·순원 관리, 모임 생성·조회, 녹음 구간 전송 및 전사 상태, 전사문 편집, 화자 연결, AI/로컬 보고서 생성과 편집, DOCX 양식 등록·미리보기·공유 흐름을 구현했습니다. API 키는 서버에서만 관리합니다. Mock STT는 iOS에서 제공하지 않습니다.

## Mac에서 실행

1. Xcode와 XcodeGen을 설치하고 `cd ios && xcodegen generate`를 실행합니다. 생성된 `MOIMLOG.xcodeproj`를 열어 서명 팀과 Bundle Identifier를 설정합니다.
2. iOS 16 이상 기기 또는 시뮬레이터에서 실행하고 기기에서 접근 가능한 기존 서버의 **HTTPS** 기본 주소를 입력합니다. 하위 경로에 배포된 경우 그 경로까지 입력합니다. iPhone에서 접근 가능한 주소여야 합니다. 운영 서버는 `COOKIE_SECURE=true`로 설정하세요. 서버 연결 확인 후 주소는 기기에 저장되고, 서버의 7일 로그인 쿠키는 서버 URL별 Keychain에 저장됩니다. 비공개 Codespaces 서버를 테스트 목적으로 임의로 Public으로 변경하지 않습니다.
3. 기존 계정으로 로그인하고 내 정보에서 순원을 등록합니다. 새 모임을 만든 뒤 기록에서 열어 녹음 또는 파일 업로드, 전사 확인, 화자 연결, 분석, 보고서 수정과 저장을 진행합니다. DOCX 생성 전 내 정보에서 교회 원본 양식을 등록해야 합니다. 새 양식을 등록하면 서버의 기존 양식이 교체됩니다.
4. 기존 데이터 보존을 위해 iOS에서는 보관 기간을 줄일 수 없습니다.

## 검증 상태와 남은 작업

- Mac의 Xcode에서 **빌드 성공, 컴파일 오류 0개**를 확인했습니다. 시뮬레이터는 연결·부팅 시간 초과로 실행 검증을 완료하지 못했습니다. 실제 서버 주소와 계정이 제공되지 않아 인증 쿠키 유지·만료, 계정 격리 및 전체 흐름은 미검증입니다.
- 녹음은 16kHz, 16비트 모노 PCM WAV를 약 14초 단위로 기기에 보관하고 서버의 순번별 엔드포인트에 전송하도록 구현했습니다. 서버는 15초 이하 구간을 요구합니다. 중단 시 화면에서 일시정지하고, 재진입 시 저장된 구간과 서버 상태를 확인해 누락 구간을 재전송합니다. 종료 요청도 기기에 보관합니다. 실제 기기의 WAV 인코딩, 중단·권한 거부, 디스크 부족, 연결 복구, 120분 제한 및 Groq 전사를 검증해야 합니다. 강제 종료나 저장 실패로 작성 중이던 마지막 구간은 손상되거나 유실될 수 있습니다. 손상된 로컬 구간을 검사·복구하는 UI는 아직 없습니다.
- 녹음 중 화면을 벗어나면 일시정지합니다. iOS가 앱을 종료한 동안에는 자동 전송되지 않으므로 화면을 다시 열어 동기화를 확인해야 합니다. 기기 원본은 자동 삭제하지 않습니다.
- 서버 분석·DOCX는 기존 서버 설정, Groq Free 한도와 호환되는 교회 양식이 필요합니다. 실서버에서 분석 결과, 미배정 발언, AI 추론 표기, 문서 미리보기와 파일 앱 저장을 검증해야 합니다.
- 웹의 기록 삭제 및 계정 삭제는 iOS에서 지원하지 않습니다. 접근성, 다크 모드, 큰 글씨 및 다양한 네트워크 상황도 검증해야 합니다.

## 이번 개발에서 진행한 작업 — Phase 1

기존 iOS APIClient와 로컬 FastAPI의 `backend/app/main.py`, `schemas.py`를 비교하고 서버 연결 및 인증 흐름을 보완했습니다. **코드 구현과 빌드 성공은 실제 서비스 동작 검증과 구분합니다.**

| 항목 | 구현 내용 |
| --- | --- |
| 서버 주소 | HTTPS만 허용하고 사용자명·비밀번호·쿼리·프래그먼트가 포함된 주소를 거부합니다. 연결 확인 또는 로그인 성공 후 주소를 UserDefaults에 저장합니다. |
| 연결 확인 | `GET /api/config` 응답을 디코딩해 MOIMLOG 서버 연결 여부를 확인합니다. |
| 회원가입·로그인 | 기존 JSON 규격과 `X-Moimlog: 1` 헤더를 유지하고 입력값 검증과 중복 요청 방지를 추가했습니다. |
| 세션 저장 | `moimlog_session`과 만료 시각을 서버 URL별 Keychain에 저장합니다. 비밀번호는 저장하지 않습니다. |
| 로그인 복구 | 재실행 시 저장된 쿠키를 메모리 전용 URLSession에 복원하고 `GET /api/me`로 프로필을 확인합니다. |
| 연결 장애·만료 | 네트워크 장애에서는 저장된 세션을 유지합니다. 인증된 JSON API 요청의 401 응답에서는 세션을 정리하고 재로그인을 안내합니다. |
| 로그아웃 | 서버 로그아웃 요청 후 로컬 세션을 삭제합니다. 서버 연결 실패 시 기기 로그아웃과 서버 세션 종료 미확인을 구분해 안내합니다. |
| 오류 안내 | 연결 실패, 시간 초과, 인증서 오류, 접근 제한, 입력 오류, 요청 제한, 서버 오류 및 응답 형식 오류에 한국어 안내를 제공합니다. |
| 로그인 화면 | 서버 연결 확인, 저장된 로그인 재확인, 처리 중 표시 및 입력 조건에 따른 버튼 비활성화를 추가했습니다. |
| 리디렉션 | 자격 증명이 다른 주소로 전달되지 않도록 자동 리디렉션을 거부합니다. 최종 HTTPS 서버 주소가 필요합니다. |

서버는 현재 7일 세션을 발급하며 갱신 API가 없어 만료 후 재로그인이 필요합니다. 이전 버전의 공유 쿠키 저장 방식에서 업데이트할 경우 최초 한 번 다시 로그인해야 합니다.

## 실제 서버 검증 및 다음 작업

1. 기기에서 접근 가능한 HTTPS 서버 주소를 입력하고 **서버 연결 확인**을 누릅니다.
2. 기존 계정 정보를 앱에 직접 입력해 로그인하고 프로필·순원·모임 기록을 확인합니다. 비밀번호나 API 키를 README 또는 소스 코드에 기록하지 않습니다.
3. 앱 종료·재실행, 네트워크 장애 후 복구, 로그아웃 후 재실행을 확인합니다.
4. 승인된 테스트 환경에서 회원가입, 잘못된 비밀번호, 세션 만료 및 서버 간 계정 격리를 확인합니다.
5. Phase 1 실서버 검증 후 아래 순서로 기존 기능을 보완하고 검증합니다.

| 단계 | 다음 작업 |
| --- | --- |
| Phase 2 | 순원 조회·수정, 기존 모임 조회 및 새 모임 생성 검증 |
| Phase 3 | 마이크 권한, 120분 녹음, 일시정지·중단·복구, 구간 전송 및 Groq STT 검증 |
| Phase 4 | 전사문 편집, 미확인 화자 처리, AI 분석 결과 검토 및 저장 |
| Phase 5 | 보고서 수정, 원본 DOCX 양식 유지, 파일 앱 저장 및 공유 |
| Phase 6 | 작은 화면, 다크 모드, Dynamic Type, VoiceOver 및 전체 흐름 안정화 |

업로드·다운로드 전용 경로의 오류 처리 통합과 편집 중 세션 만료 시 초안 보존은 추가 안정화가 필요합니다. 자세한 확인 절차는 [Phase 1 검증 기록](PHASE1_VALIDATION.md)을 참고하세요.

## Groq 무료 운영 원칙

- STT는 `whisper-large-v3-turbo`, AI 분석은 `openai/gpt-oss-120b`를 사용합니다.
- Groq API 키는 서버에만 보관하며 iOS 앱에 포함하지 않습니다.
- 다른 유료 API로 자동 전환하거나 결제 기능을 추가하지 않습니다.
- 무료 사용량 제한 시 원본 보존과 대기·재시도 흐름을 검증해야 합니다.
- 화자 미확인 발언을 특정 순원에게 임의로 배정하지 않고, AI 결과는 순장의 검토를 거칩니다.
