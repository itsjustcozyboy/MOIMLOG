# Phase 1 — 서버 연결 및 로그인

## 구현 범위

- 로컬 `backend/app/main.py`, `schemas.py`와 iOS 요청/응답 모델을 비교했다.
- `GET /api/config`: MOIMLOG 응답을 디코딩해 연결을 확인하고 HTTPS 주소를 UserDefaults에 저장한다.
- `POST /api/auth/register`, `POST /api/auth/login`: 기존 JSON 규격 및 `X-Moimlog: 1`을 유지한다.
- 서버가 발급한 `moimlog_session` 쿠키와 만료 시각을 서버 URL별 Keychain에 저장한다. 비밀번호는 저장하지 않는다.
- 메모리 전용 URLSession 쿠키 저장소를 재사용하며, 재실행 시 Keychain 복원 후 `GET /api/me`로 유효성을 확인한다.
- `POST /api/auth/logout`: 서버 로그아웃을 요청하고 로컬 Keychain 및 쿠키를 삭제한다. 서버 연결 실패 시 로컬 로그아웃과 서버 종료 미확인을 구분한다.
- 연결 실패, 시간 초과, 인증서 오류, 접근 제한, 401, 422, 429, 서버 오류, 잘못된 응답에 한국어 안내를 제공한다.
- 자동 리디렉션을 거부한다. 최종 HTTPS API 주소를 사용해야 하며 Codespaces 접근 제한을 우회하지 않는다.
- 기존 프로필/순원/모임 API 및 화면을 보존한다. Phase 2 이후 기능의 완성·실서버 검증을 의미하지 않는다.

## 확인 결과

- Xcode `BuildProject`: 성공, 컴파일 오류 0개.
- `git diff --check`: 통과.
- `SessionStore.swift`: Xcode Sources에 포함됨. XcodeGen의 기존 MOIMLOG 폴더 소스 설정으로도 포함됨.
- `project.yml`, `Info.plist`, FastAPI 코드, Groq 설정은 수정하지 않음.
- HTTPS 주소 검증 및 Keychain 동작을 실행하려던 RunCodeSnippet은 런타임 준비 시간 초과로 결과를 얻지 못함. 실행 검증 성공으로 간주하지 않음.
- 실제 서버 URL/계정 미제공: 실제 인증, 재실행 복구, 데이터 로드 미검증.

## 실제 서버 확인 절차

1. 접근 가능한 HTTPS 서버 주소를 앱에 입력하고 ‘서버 연결 확인’을 누른다. 서버의 `/api/config`가 JSON을 반환해야 한다.
2. 기존 계정은 앱에 직접 입력해 로그인한다. 프로필과 기존 모임 목록을 확인한다.
3. 앱을 종료하고 다시 실행해 같은 프로필로 복구되는지 확인한다.
4. 네트워크를 끊고 재실행한다. 연결 안내 후 네트워크 복구 시 ‘저장된 로그인 다시 확인’으로 복구되는지 확인한다.
5. 로그아웃 후 앱을 재실행해 자동 로그인되지 않는지 확인한다.
6. 사용자 승인을 받은 테스트 계정으로 회원가입과 중복 이메일/잘못된 비밀번호 오류를 확인한다.
7. 테스트 환경에서 세션을 만료시키고 재실행해 로그인 안내를 확인한다.
8. 서버 A/B 간 전환 시 서로의 세션이 전달되지 않는지 확인한다.

서버 주소에는 사용자명·비밀번호·쿼리 토큰을 넣을 수 없다. 저장된 쿠키를 쓰던 이전 앱 버전에서 업데이트할 경우 최초 한 번 재로그인이 필요하다. 서버는 현재 7일 세션을 발급하며 갱신 API가 없어 만료 후 다시 로그인한다.
